Geometry stays fixed

Always reserve slots for the check mark and icon. Change backgrounds and overlays without adding padding, borders or width.

08 / Commands

Enter uses colour. Alt uses a letter.

Do not append a keyboard manual to every caption. A primary button, an access key and an accelerator are three different concepts.

Recurring mistake
Target appearance
Button component states

Hover, press or use Tab: CSS shows hover, pressed and focus states without changing the dimensions.

Blue identifies the actual Enter target in the current context: Search in the query form, Go to file in results. An underlined letter must not promise a binding that has not been implemented.

Evidence: #34, #38–39 and open #79. In Avalonia, use AccessText with an underscore (_panel), not a literal Windows ampersand. F3 may appear as a separate secondary hint. Never show two defaults in the same context.

14 / Visual and usability audit

Check beyond the happy path.

Visual review: alignment, rhythm, hierarchy and contrast. Usability review: understandable states, discoverable commands and visual promises that match actions.

ScenarioWhat the presentation must withstand
100% / 150%Crisp system icons, readable text and no clipped rows
Minimum window widthEssential actions remain visible; groups wrap; tables scroll within their own viewport
Long path / Cyrillic / CJKThe useful path ending stays visible, the full value is available and row height stays stable
Cursor + mark + matchAll three meanings remain distinct without changing geometry
KeyboardVisible focus; default matches Enter; no access-key conflicts within a scope
Empty / full / error / disabledHierarchy remains clear; essential messages are not hidden to save space
Reduced colour discriminationCheck marks, labels, underlines and the active boundary supplement colour
Audit conclusion: the interface needs shared components and state semantics, rather than a cosmetic theme change. Keep its dense character and familiar Windows conventions; remove local inconsistencies.

This assessment uses source code and three real offscreen renders. Independent usability review of the changed application and a fresh render pass are needed during implementation; this document does not claim to have completed them.

17 / Working standard

Every new screen
starts with these rules.

01

Choose a component

A table, form, message or action row. Do not invent new layouts for repeated data.

02

Compose the states

Cursor, marks, focus, default, disabled and error. Check combinations and the actual Enter target.

03

Check the render

100/150%, minimum width, long paths, empty and populated screens. Check the actual controls.

Suggested first step: fix the open comment about search buttons and extract shared button / action-row styles. Then standardise tables using real renders.
