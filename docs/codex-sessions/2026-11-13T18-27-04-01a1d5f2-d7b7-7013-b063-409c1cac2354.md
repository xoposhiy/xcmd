### Codex final reply

> **Xcmd использует внешний Git CLI, а не библиотеку вроде LibGit2.** Для Git-функций нужен установленный `git`, доступный через `PATH`. Графический Git-клиент не требуется. Сам Xcmd запускается из готового комплекта файлов; требуется .NET 10. См. [требования запуска](C:/work/projects/xcmd/README.md:11).
>
> Что происходит при сбое:
>
> | Функция | Поведение |
> |---|---|
> | Ветка, счётчики, статусы файлов | При отсутствии Git, ошибке команды или тайм-ауте индикаторы очищаются. Причина пользователю не показывается. Файловые панели продолжают работать. |
> | Поиск с учётом Git ignore | Поиск продолжается, ошибка попадает в список проблем. Правила Git ignore перестают применяться, поэтому результаты могут включать обычно игнорируемые файлы. |
> | **Commit with AI** | Дополнительно нужны установленный Claude Code и вход в него. Ошибка подготовки или запуска показывается в строке состояния; панели остаются доступны. |
>
> Реализация статуса достаточно защищена: запросы выполняются в фоне, обновляются раз в три секунды, имеют общий тайм-аут пять секунд, отменяются при переходе в другую папку. Зависший процесс завершается. Используется машинный формат `--porcelain=v2 -z`, аргументы передаются отдельно от командной строки. Это снижает хрупкость разбора и проблемы с путями. [Запуск Git](C:/work/projects/xcmd/src/Xcmd.Infrastructure/GitStatusReader.cs:44), [обновление интерфейса](C:/work/projects/xcmd/src/Xcmd.Desktop/GitStatusView.cs:101).
>
> Основные слабые места:
>
> - **Сбои статуса полностью скрыты.** «Это не репозиторий» и «Git сломан» выглядят одинаково. Большой репозиторий, не укладывающийся в пять секунд, тоже может остаться без индикаторов.
> - **Обработка Git реализована тремя отдельными способами.** Например, статус и подготовка коммита очищают унаследованные переменные `GIT_*`, а поиск — нет. Поэтому окружение запуска может повлиять на выбор репозитория при поиске. [Git в поиске](C:/work/projects/xcmd/src/Xcmd.Infrastructure/SearchGitScope.cs:62).
> - **Поиск может повторять неудачные вызовы для каждой папки.** При зависании Git возможны повторные задержки до десяти секунд; общего отключения после первой ошибки нет. [Продолжение поиска после ошибки](C:/work/projects/xcmd/src/Xcmd.Infrastructure/FileSearchSource.cs:37).
>
> Моя оценка: **для обычного использования интеграция разумно устойчива, но диагностика и работа при длительных сбоях требуют улучшения**. Фоновое чтение не выполняет `add`, `commit`, `reset` или `fetch`; основной эффект отказа — потеря индикации и изменение поведения поиска.
