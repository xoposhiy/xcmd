### User prompt

> And after this I want you to do a usability review, look again from the perspective of a usability specialist at this entire Git interface that we came up with together, and find any inconsistencies, rough edges, things that can be improved, optimized, made clearer and more logical.

### Codex final reply

> Провёл независимый review и проверил спорные переходы headless-прогоном реальных контролов. Получилось **11 замечаний**. Основные:
>
> 1. **Ломается выход через Escape.** Если перенести Git-папку в другую панель через Ctrl+Left/Right, её исходная папка не запоминается. Escape после этого ничего не делает. Это самый высокий приоритет.
>
> 2. **Исторический файл теряет свой контекст в просмотрщике.** После F3 заголовок показывает временный путь без коммита. F4 передаёт редактору эту временную копию без пояснения, хотя в панели редактирование запрещено. Нужно сохранять путь, SHA и признак read-only.
>
> 3. **`Modified` вводит в заблуждение.** Всем файлам снимка присваивается дата коммита, включая неизменённые. Лучше показывать неизвестную дату или явно назвать её датой снимка.
>
> 4. **Working tree показывает разные состояния.** Панель сохраняет старый список, а F3 уже показывает свежие изменения. Нужны единое правило обновления и понятная подсказка про Ctrl+R.
>
> 5. **Copy ведёт в тупик.** Ctrl+C советует извлечь файл из «архива» через F5, а F5 запрещён. Сообщения и доступность команд нужно согласовать.
>
> 6. **Удалённый файл трудно сравнить.** Он присутствует только в текстовом отчёте изменений, откуда нельзя выбрать его для Diff. Здесь нужен доступ к действиям над изменёнными файлами при сохранении полного дерева по Enter.
>
> Есть и менее крупные шероховатости:
>
> - пустой журнал предлагает выбрать отсутствующий коммит;
> - Ctrl+F6 не сортирует журнал, но неожиданно меняет сортировку следующего снимка;
> - легенда Git-колонки в снимке говорит про working tree;
> - журнал показывает бессмысленные `≥ 0 bytes (incomplete)`;
> - SHA местами обрезаются, отступы заголовков и значений различаются.
>
> **Базовую схему стоит сохранить:** отдельный формат журнала, обычное дерево внутри коммита, постоянное сообщение снизу и Working tree с фильтрацией по пути.
>
> [Полный отчёт с доказательствами, приоритетами и рекомендациями](http://localhost:57076/docs/evidence/git-usability-review-2026-11-13.md).
>
> Первым пакетом рекомендую исправить выход, контекст просмотрщика, ложные даты и ошибочные сообщения. Интерфейс в рамках review не менял.
