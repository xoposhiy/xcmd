Scoring rubric

Read the role, epic and earlier catalogue context. Score the short “As a…” statement on each of the six criteria below. Compare related stories across epics for B. Add the six scores with equal weight for a total from 0 to 12. Keep ties. A one-point difference is a prompt to compare the reasons.

For F, try to construct an example where one part succeeds and the main job still fails. In a list of commands, also ask whether the commands are alternatives within one choice or separate jobs. For N, keyboard navigation, clipboard exchange and OS-independent rules can themselves be user or developer needs. A named UI surface or technical term alone earns no deduction.

For T, describe one situation, action and expected result. A dependency check, a second caller or a failed shutdown can provide developer evidence. Read attached decisions to find examples or possible repairs. The score describes how much the short statement conveys. A long decision history, a missing checklist and the number of mapped files have no score. Estimating team effort and sprint size would require planning data beyond this catalogue.

Calibration. FollowLog earns 12/12. Append a line to a file while the viewer follows its end. Seeing the line without reopening the file confirms exactly what the user gains. FeedbackQueue also earns 12/12 despite five verbs. Two agents claiming the same item expose one clear rule about who owns the work. In ControlSearch, recalling an old query can work even when stopping a running query fails.

Lowest scores and what to clarify

5 stories score 7 or below. The list includes all ties at that cutoff, followed by ReadablePanels, the next-lowest end-user story. The proposed questions and examples are for discussion.

AsyncCoordination · 3/12

“Visible process and UI ownership” leaves the developer without a success condition. ApplicationLifecycle also claims host composition and background work.

Refinement question or example. Start with one pending action and its owner. When the owner closes, what must the developer be able to observe about the action? Decide whether routing actions addresses that same need.

ApplicationLifecycle · 6/12

Composing the host, disposing work and diagnosing failures can each succeed while another fails. The recorded startup-time decision does not define successful shutdown.

Refinement question or example. Use one service at shutdown as the example. What would tell the developer that its lifetime ended correctly? Compare that answer with AsyncCoordination before assigning responsibility.

ControlSearch · 7/12

A user can recall yesterday’s query while cancellation is broken, or stop a search while history is broken. “Without unclear background changes” does not say what happens to the results already on screen.

Refinement question or example. Use the existing agreement that editing query options preserves current results and restarting applies new settings. Ask whether recalling older queries needs its own statement.

SharedControls · 7/12

“Presentation mechanics” groups layout, styling and list rendering. Reusing a layout gives no evidence that selection behaves consistently in two lists.

Refinement question or example. Use the recorded selection example. What should a developer be able to reuse when adding a new list so that hovering never looks like a second selection? Check whether layout has the same acceptance example.

SyntaxSpans · 7/12

A second consumer could reuse syntax ranges even if the chosen colors were unreadable. A palette change could improve readability without making the ranges reusable.

Refinement question or example. Identify a consumer of the same syntax information and what it must reuse. Discuss readability in its own example. The recorded decision defers export commands, so this example need not add an export feature.

ReadablePanels · 8/12

A user can fit the name and size columns on screen while file types remain indistinguishable. Recognizing extensions by color also helps when there is plenty of space.

Refinement question or example. Use two examples from the decisions. Resize a narrow panel and check the visible metadata. Then identify a script among other entries by its type color. Decide whether each deserves its own statement.

Possible wording for the query-editing part of ControlSearch.

As a user, I want to change a search query without losing the results already on screen so that I can review the current matches before starting the revised search.

This draft covers the recorded behavior for editing search options. Stopping a running search and recalling past queries still need an explicit place if the story is revised.
